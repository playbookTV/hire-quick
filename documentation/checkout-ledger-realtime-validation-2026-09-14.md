## Runtime and policy limits

New access tokens bind to the current refresh identifier. Legacy access remains REST-compatible until expiry, while legacy sockets require refresh/login and reconnect. Rotation requires reconnect with the replacement access token. Logout affects the supplied refresh token; independent logins remain valid. Account status, role, expiry and revocation are checked at each action and private delivery, with another session check before private acknowledgment/emission. Idle sockets expire on a timer. These checks do not recall packets already authorized or in flight.

Socket traffic uses shared strict message bounds, per-user quotas and bounded per-socket queues. Redis transports envelopes to recipient-authorizing API nodes; workers cannot bypass that path. Redis outage drops convenience signals without an offline buffer or local fallback; API reads recover authoritative state. This is not a durable outbox implementation. HTTP server/worker shutdown closes realtime Redis resources; a comprehensive shutdown deadline policy remains outside this batch.

The local Redis result is an actual transport check with mocked DB ports, not proof of deployed multi-host behavior. Native checkout/reconnection acceptance, browser provider checkout, actual TEST-provider certification, live financial activity, merge and deployment are not claimed. Checkout privacy export/erasure and late-refund receipts must pass final integration before ticket advancement. Checkout email and hosted URLs are scrubbed, but the existing financial idempotency request fingerprint can retain the input email. Root recorded this remaining inventory/retention work on OVA-146 (still Todo), preserving replay semantics. This batch does not claim every personal-data copy is erased.
